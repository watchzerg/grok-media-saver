# 实现路线图

状态：已确认的整体路线。确认日期：2026-09-25。

本路线图服务于[产品目标与首版范围](../specs/product-goals.md)，以[架构设计](../../ARCHITECTURE.md)为契约。本文记录各期范围、依赖、风险验证时点和结束标准，不作为实现或验收证据；二期当前实现与自动化覆盖见[单 Post 完整归档规格](../specs/phase2-archiving.md)及[交付覆盖核对](../research/phase2-acceptance.md)，ticket 生命周期与正式验收记录以 Beads 为入口。一期具体契约见[一期可靠保存规格](../specs/phase1-saving.md)。

## 整体顺序

采用一轮整体设计收口加三期实现：

```mermaid
flowchart LR
    A[跨期设计收口] --> B[一期：可靠保存第一页]
    B --> C[二期：单 Post 完整归档]
    C --> D[三期：批量归档首版]
```

贯穿三期的 Run 与 Post 关系、保存与移除状态、媒体身份、停止及重试、批量结束条件已在架构中确定。函数、SQL、具体节奏和重试次数在相关一期开始前细化。自动重试额度采用内存计数，重启可重新计算；恢复事实持久保存；全局阻挡只控制当前 Run。

只读检查作为一期的首个内部切片；必要状态、停止及恢复能力随对应行为一起交付，不另设最后的可靠性或控制体验补齐期。

## 一期：可靠保存第一页

**目标：** 通过正式应用路径读取 Saved 列表第一页并逐 Post 可靠保存，保存完这一页即结束，并能够重试中断遗留。指定 Post 保存作为同一路径的入口。

范围：

- Application runtime 和最小 CLI；按用例初始化资源与退出清理。
- Browser session 连接、请求、断开、重新连接和自建资源清理。
- 第一页与指定 Post 的读取、身份及媒体解析；只读检查可保留为诊断入口。
- API 节奏与独立媒体传输；认证、限流、停止和必要状态展示。
- Bun 内建 `SQL` 接入 PostgreSQL、显式 `db init`、单执行器互斥、Run 与 Post 工作的最小持久关系；普通命令不自动建表或迁移。
- 文件校验、发布、复用、缺失与冲突处理，以及显式恢复。

先验收连接和解析，再完成媒体传输及持久恢复。首次持久处理就采用架构确定的 Run 与 Post 关系，按本期需求实现字段；不等三期重新引入一套任务体系。

**结束标准：** 图片和常见小视频通过正式应用路径完整保存并可停止；文件发布与数据库提交之间的中断可恢复；冲突不覆盖；状态如实表达已保存；第一页处理完即结束，单 Post 失败继续，跨 Run 重试按确定集合执行。只保存入口保持阶段性验证用途，不扩展为独立产品模式。按 2026-09-26 用户范围修订，大视频专项支持、慢写、回压上界与峰值内存验收不在本期，也不是延期必补项。

**交给下一期：** 已核验的保存结果、统一 Post 处理路径、持久恢复、资源管理、API 调度与状态输出能力。尚未提供远端删除或连续读页归档。

## 二期：单 Post 完整归档

**依赖：** 一期可靠保存及文件恢复的必要自动化验证通过；二期实现交付不等待用户现场环境或人工操作。

在同一 Post archiver 中加入：

- 删除资格核验、持久删除意图和精确 DELETE。
- 成功、明确失败及结果未知的区分。
- 未知结果核对与恢复。
- 删除期间的停止及退出收尾。
- 已保存未移除状态的继续处理。

复用一期下载、文件核验、数据库、API 调度、资源管理和状态输出，不新增独立删除任务系统。

**自动化交付标准：** 单 Post 从开始到完整归档的契约及受控故障均有自动化证据；未安全保存不删除；失回执或重启后先核对未知结果，不盲目重复删除。最终干净候选通过无筛选 `just gate-full`，实现票可以独立自动化完成。正式现场验收由用户在实现交付后人工操作，不属于实现票完成或三期开发的前置条件；交付报告明确其未执行状态，并附简短操作清单。具体行为、测试观察接口、矩阵及交接条件见[二期规格](../specs/phase2-archiving.md)，决策过程保留于 `grok-media-saver-we2`。

**交给下一期：** 可被重复调用和恢复的完整单 Post 归档能力。此时仍未交付持续处理第一页的批量流程。

## 三期：批量归档与首版交付

具体行为、结果、approved S1/S2、自动化矩阵、实施切片及当前实现说明以[三期批量归档规格](../specs/phase3-batch-archiving.md)为权威正文，决策来源为 `grok-media-saver-ozd`。当前 CLI 已提供 `archive saved`；批次自动化交付仍以最终候选的门禁与矩阵核对为证据，正式现场验收未执行，由用户后续人工操作。

**依赖：** 二期单 Post 完整归档及删除恢复的自动化门禁与契约覆盖通过；用户后续人工现场验收不阻塞三期开发。

Run controller 复用一期单页保存调度和二期单 Post 归档路径，增加连续读页能力：

- `archive saved` 从当前第一页启动，每轮固定合法页面成员，不先执行历史 retry；每 Post 每 Run 一次完整处理，跨轮复用请求预算。
- 本轮新确认移除推动下一轮，普通单项失败继续，停止、全局阻挡及基础故障优先结束。
- 固定 5 秒可取消轮间等待、No Progress、合法空页与全部 save/archive 遗留工作共同决定结果；不翻页绕过阻塞项。
- 同页及跨轮去重、重现跳过，本次结果与数据库遗留快照分开，未知不补零。
- 批量状态汇总、失败项查看、显式恢复及实际 CLI 操作说明。

本期主要增加调度与汇总。若必须重写下载、删除或恢复才能接入批量，应先修正公共处理路径，再扩大处理范围。

实施依赖顺序为：单 Post 新确认移除证据 → 完整批量 Application 与摘要 → CLI/status 与真实进程交接。循环首次交付即包含停止、预算和故障约束；fixture 随行为切片建设，详细责任以三期规格为准，执行计划与子票证据由 `grok-media-saver-eev` 承接。

**自动化结束标准：** 批量契约、受控故障及真实本地恢复边界有证据，最终干净候选通过无筛选 `just gate-full` 并完成矩阵核对。安装、配置和恢复说明与实际命令一致。正式 Chrome/Extension/Grok 现场验收由用户在交付后人工执行，不作为开发完成条件；交付报告明确未验证范围并提供简短操作清单。

Web UI、字节级续传及其他超出首版范围的能力不纳入上述三期。

## 风险验证时点

| 风险 | 最迟验证时点 | 影响与处理 |
| --- | --- | --- |
| Playwright 入口在本项目运行时下的连接、关闭与重新连接 | 一期首个连接切片 | 失败先调整 Browser session，不继续堆积依赖该连接的实现 |
| 普通媒体的完整性与停止能力 | 首次图片/视频保存切片 | 用图片和常见小视频核对完整性、真实取消及资源清理；不要求大视频或性能压力验收，文件恢复随首次保存路径交付 |
| 删除成功及未知结果规则 | 设计时审视证据，二期自动化验证契约与受控故障；交付后由用户人工验证现场 | 已知契约失败须解决；潜在现场问题不阻塞自动化完成，后续发现具体问题再建立修复或决策任务 |
| 文件与数据库不一致的恢复 | 一期内 | 未通过不进入二期删除 |

省去逐 Post 导航等优化只做有限探索，证据不足时采用已有验证路径。[已迁入的调研与原始 demo](../research/2026-09-25-grok-playwright-extension-demo.md)是可行性参考，不替代本项目正式路径验收。

## 减少跨期重叠的约束

- 公共设计以架构为准，各期补充实际需要的细节，不重复建立状态模型或处理入口。
- 一期建立资源管理、保存和文件恢复；二期扩展删除及其恢复；三期扩展连续读页调度和汇总。
- 新副作用与恢复同期交付。状态查看、停止和故障说明随能力一起交付。
- 从一期逐步建立真实 PostgreSQL、临时归档目录及受控外部响应测试能力；浏览器自动化采用架构规定的方案 A，在项目能力接口使用 mock / fake。真实 Chrome + Playwright Extension + 本地受控服务的方案 B 暂不建设，后续由用户决定是否启用。
- 各期新增必要行为验证，并纳入相应 just gate；门禁不依赖 Chrome、Extension token 或 Grok 登录态。基础静态检查和 mock 不替代真实浏览器证据；真实连接、媒体传输、停止和清理按现场验收记录。二期正式现场验收由用户在实现交付后操作；真实删除仍须明确授权具体样本，未执行现场验收不阻塞二期自动化交付或三期开发。
- 全部阶段的目标和依赖现在确定，只细拆即将实施的一期。每期开始前完善规格、验收方式和执行任务。
- 开发阶段默认按当前代码、新 schema 和新任务验收，不默认支持跨期版本兼容或试运行数据迁移。若需保留旧阶段试运行数据并继续使用，先明确需求与成本；不自动清除已有数据。
