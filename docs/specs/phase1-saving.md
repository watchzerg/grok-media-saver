# 一期：可靠保存第一页

状态：已确认的一期规格。确认日期：2026-09-26。本文不表示应用或验收已经完成。

## 目的与权威边界

一期通过正式应用路径读取 Saved 列表第一页，串行保存其中每个 Post 的主体媒体，处理完这一页后结束；同时提供指定 Post 保存、只读检查、状态、核验与跨 Run 重试。

2026-09-26 范围修订：本期面向 AI 生成图片和常见小视频，不建设大视频专项支持，不要求大视频样本、慢写压力测试、回压/在途块上界或峰值内存验收，也不将其作为交付阻断或延期必补项。不新增文件大小阈值或拒绝规则；普通媒体的完整性、超时、真实停止、资源清理和文件恢复要求保留。

本文作为一期具体行为、持久事实与验收的单一规格正文。产品目标见[产品目标与首版范围](product-goals.md)，跨期职责见[架构设计](../../ARCHITECTURE.md)，术语见[领域词汇](../../CONTEXT.md)，阶段范围见[实现路线图](../development/implementation-roadmap.md)。Beads 保留决策过程及确认记录；研究文档提供观察证据，不自行改变规格。

本期仅面向当前代码、新 schema 和新启动任务。远端 DELETE、未知删除结果核对、连续读页、Web UI、多账号、旧数据迁移、跨版本兼容、字节级续传、自动安装环境和可执行文件分发均不在一期。后续完整归档仍要求保存及确认移除；一期 `saved` 仅表示保存完成。

## 命令与结果

以 mise 管理的 Bun 直接运行 TypeScript；以下是应用参数契约，入口文件名和具体配置键在实现时确定。

| 命令 | 行为与资源 |
| --- | --- |
| `inspect first-page` | 只读检查一次 Saved 第一页，不逐条展开详情；只需浏览器与调度 |
| `inspect post <Post ID>` | 只读检查指定 Post 身份及媒体；只需浏览器与调度 |
| `save first-page` | 读取一次第一页，按顺序逐 Post 保存；需要 DB、归档目录与浏览器 |
| `save post <Post ID>` | 调用相同 Post 处理路径保存指定目标 |
| `retry` | 启动时固定跨 Run 的非 `saved` 集合，每项一轮；无目标不连接浏览器 |
| `status` | 只查询 DB，展示最近 Run 摘要和当前未完成 Post，不访问浏览器或文件 |
| `verify <Post ID>` | 读取 DB，在当前归档目录核验文件，仅报告，不修复或改写工作状态 |
| `db init` | 在用户已准备的项目 DB 中建立当前 schema；不创建数据库、不清空数据、不创建 Run |

Post ID 只接受带连字符的 `8-4-4-4-12` 位十六进制 UUID：去首尾空白，转小写，不限制 UUID 版本。不接受整段 URL、conversation 参数或媒体地址。参数错误须在资源启动前报告。

一期 `retry` 不选择 `saved`；显式 `save` 再次遇到已保存 Post 时重新处理，保留旧成功版本并重读详情。第一页中尚未开始处理的成员不预建工作记录。普通单 Post 失败继续其余成员；全局阻挡、停止或基础资源故障结束整次执行。不循环到全部成功。

终端文本展示当前阶段、结果及已知成功/失败/未处理数量，不增加完整 JSON 协议、交互选择或终端面板。退出码：成功（含空页/空重试集合）为 `0`，失败/未处理/阻挡/核验异常为 `1`，参数或配置错误为 `2`，Ctrl+C 为 `130`。`status` 成功展示历史失败仍返回 `0`。清理失败使原本成功的命令返回 `1`，保存事实继续有效；停止仍返回 `130` 并报告清理错误。

## 配置与初始化

提供 `.env.example` 占位示例，本机 `.env` 保存实际值。优先级为进程环境变量 > env 文件 > 程序默认值；配置在本进程内固定。按用例仅校验所需配置，错误中隐藏密码、token 及含 token 的连接 URL。

配置包含拆分的 DB 地址、端口、用户名、密码、数据库名，归档根目录，列表起点 URL，Playwright Extension 连接 token，共享间隔上下限及媒体超时。列表默认 `https://grok.com/imagine/saved`，保持唯一 Saved 来源，不扩展任意抓取。token 是扩展连接凭据，不是 Grok API key。

DB 与归档目录独立，不绑定根目录。文件定位使用当前根目录和 DB 中相对路径；换目录不搜索旧目录。未完成工作缺失文件时可重新下载，远端不可获取则报告未完成。`status` 不因文件事后移动推翻历史事实。

`db init` 使用一份当前 schema SQL。结构完全一致时重复执行成功，不一致时报错；不以表名存在代替结构核对。普通命令只检查所需结构，不自动建表或迁移。采用 Bun 内建 `SQL`；浏览器采用 `playwright-core`，连接入口封装在 Browser session。依赖遵循项目版本与 lockfile 规则。

## Post 身份、媒体选择与复用

详情必须是当前支持的 JSON 根对象，返回 `assetId` 必须匹配目标 ID。未知包装、身份不符、主体缺失或不唯一均失败，不猜测 fallback 或静默选第一项。

每个 Post 只保存一份主体媒体：图片取根 `key`；视频按已经存在的 `hd1080Key` → `hdKey` → 根 `key` 选择。高清字段明确缺席时才选择下一档；最高已知候选存在但无法解析或获取时失败，不降级。不保存关联 Post、生成输入、封面、缩略图或 `auxKeys` 中的 original-image；不生成或增强媒体。

直接复用需要同时满足：Post ID、所选画质、详情所选 key 未变，适用于所选对象的已知类型/大小无冲突，当前目录文件的大小与 SHA-256 符合保存记录。该取舍不检测相同 key 和元数据下的服务端字节替换，不以播放器临时 URL 定义版本。

来源或元数据变化则重新下载。新内容与该 Post 已有 SHA-256 相同，核验已有文件后复用并更新当前关联；摘要不同则保留旧文件并新增版本。不做跨 Post 去重。文件缺失可重新下载；现有文件冲突不覆盖、不自动换名。再次 `save` 失败时当前工作可为 `failed`，旧成功版本仍保留。

## 请求、传输与停止

### 共享调度和错误分类

列表、详情和每次完整媒体请求及重试共用串行许可。首个请求直接发出；每次实际发出后为下一请求均匀抽取一次间隔，默认 5～8 秒，按发起时间计算，等待中不重抽。当前请求结束后才能发出下一请求；长请求耗尽间隔后无需额外等待。

上下限以秒配置，须为有限数且 `0 ≤ min ≤ max`，相等表示固定间隔。不增加累计休息、媒体专属间隔或额外退避。媒体内部 chunk 不取许可、不计次数。该间隔不保证 Grok 不限流，也不能控制页面自身后台请求。

列表及详情 API 从实际发起到响应体读完固定总超时 30 秒。网络错误、超时、HTTP `408` 或 `5xx` 最多重试一次；其他错误不重试。列表最终失败结束执行，详情最终失败结束当前 Post。API 和媒体额度分别管理，媒体不叠加 API 重试；前次请求未确认停止不得重试。

| 情况 | 处理 |
| --- | --- |
| `429`、明确登录失效、登录页或 challenge | 停止当前执行，展示原因及已知等待信息，不自动等待后恢复 |
| 普通 Post/媒体 `403`、`404`、身份不符、结构不支持 | 当前 Post 失败；有登录/challenge 明确证据时优先按全局阻挡 |
| 列表响应无法处理 | 结束执行 |
| 浏览器断连、DB/磁盘故障、丢锁、无法确认请求停止 | 基础资源故障，停止新工作与副作用并收尾 |
| 用户停止 | 取消许可等待和可中断请求，保留必要持久事实后退出 |

不追加账号健康探测。阻挡只限制当前执行，新 Run 不继承冷却许可或重试计数。只读检查遵守相同停止规则。

### 单响应媒体传输

沿用浏览器内一次完整 GET，响应流顺序交给 Bun 写独占临时文件，正确处理写入完成和失败。不为大视频增加专用缓冲队列、调优参数或内存上界保证。不拼接多个 Range 响应、不并行下载或续传；本次范围收窄不另行更换既定下载路径。正式路径不可行时回到设计调整，不自动换为 Range、整文件缓冲或 Bun 直连。

允许发布需要全部满足：

1. 身份及所选主体正确，响应为完整 `200`，类型和文件头符合媒体而非错误页。
2. 实际所选响应有有效 `Content-Length`，正常 EOF，实际写入字节数相等。
3. 详情元数据仅在适用于所选对象时交叉核对；基础视频 `sizeBytes` 不验证高清。已知长度/类型冲突不得发布。
4. 落盘临时文件大小和 SHA-256 已核验；正确处理短写。摘要用于本地版本与后续核验，不独立证明远端完整性。

已观察到 Grok 对同一图片在详情及 HTTP 响应中均声明 `image/png`，实际文件头却为 JPEG。仅对此形状，在完整响应的长度、EOF 和落盘核验通过后按 `image/jpeg` 与 `.jpg` 发布；再次处理相同 key、画质和大小时允许核验复用该 JPEG 版本。其他类型或无法识别的文件头仍失败，不因地址后缀猜测格式。

无可信长度，或内容编码使收到字节与长度不能直接比较时明确失败。目标是本次详情选中的响应，成功后不再查询详情追逐更新。

每个 Post 每 Run 最多两次媒体传输。普通网络中断、超时或可重试完整性冲突后，先确认请求与句柄停止并清理本次下载残片；有额度才重读详情、重新选择最高既有画质、从头下载。重读详情不重置媒体额度。身份不明等确定性问题不靠重复下载修复；停止、阻挡和基础资源故障不自动重试。

媒体超时可配置，默认：首字节 30 秒、连续无成功写入 30 秒、单次总时长 15 分钟；许可等待不计入。取消目标为 5 秒；超出取消目标则关闭程序自建请求页并结束执行，无法确认停止时报告清理失败，不继续下一请求。外层 Promise 返回不证明底层取消成功。

## 持久事实与事务

只保留三类记录，不建立逐 Run/Post 结果历史、逐请求日志或持久重试计数。

| 记录 | 最小事实 |
| --- | --- |
| Run | 身份、命令/目标、开始时间、可知结束时间、结束结果/原因及正常收尾汇总 |
| Post 工作 | 唯一规范化 Post ID、状态、最近 Run、所选 key/画质和适用元数据、成功版本引用、最近错误、未完成发布意图 |
| 媒体版本 | 所属 Post、SHA-256、字节数、类型、相对路径、保存时间；同 Post 同摘要唯一 |

发布意图每 Post 最多一份，内嵌于工作记录，包含临时标识、目标相对路径、预期大小及摘要；来源和类型沿用工作事实。不保存完整私人响应或凭据。

保存状态：`pending` 为已开始未完成，`finalizing` 为下载已核验且意图提交、保存待确认，`saved` 为已安全保存，`failed` 为明确失败。读取详情及下载进度不另设持久状态。未核清意图不能被普通 `failed` 或新 `pending` 清除。

只有 `save`、`retry` 创建 Run。先校验参数和配置，连接 DB/检查结构，取得全局执行器锁，将遗留运行中 Run 标为中断，再创建本次 Run；之后准备目录、按需连接浏览器。创建 Run 前的错误不造 Run，之后启动失败应记失败，DB 不可用或提交未知时不能声称已记账。

计数只在内存维护，正常收尾写摘要。异常退出缺失计数显示未知，不填零，不把下次发现时间当实际崩溃时间。只读 `status` 对未收尾 Run 提示可能仍在运行或已中断，不推断存活。

事务顺序：开始 Post 前提交工作事实；核验并同步临时文件后短事务记录意图和 `finalizing`；事务外发布及核验文件；最后短事务同时写入/复用版本、更新关联、置 `saved` 并清除意图。事务不包围浏览器或文件操作。提交失回执立即停止，不推断回滚，下次依据实际 DB 与文件核对。

同一 DB 的 `save`/`retry` 共用一把覆盖全 Run 的 PostgreSQL 专用会话锁，与归档根目录无关。竞争失败返回 `1`，不排队、不建 Run。runtime 管理生命周期，store 封装锁；在原会话解锁后释放，不以归还池替代解锁。丢锁即停止，本次不自动重连接续；不声称锁消除外部文件操作与丢锁检测间的时间窗。

## 文件发布与恢复

正式路径为 `<归档目录>/<Post ID>/<完整 SHA-256>.<ext>`，扩展名来自核验后的类型。临时文件位于同一 Post 目录，以 `.<随机标识>.part` 独占创建；不续写历史残片，不跟随符号链接把它当归档文件。

确认发布意图提交后，以 `link(temp, final)` 无覆盖落位；核验正式文件并完成必要文件/目录同步后才提交保存成功，随后清理临时名。不支持硬链接时明确失败。已有目标只在普通文件且大小/摘要符合时复用，否则报告冲突，不覆盖或换名绕过。

| 恢复现场 | 动作 |
| --- | --- |
| 意图未提交 | 不凭残片宣称保存，下次重读详情并从头下载 |
| 意图提交失回执 | 停止，不发布或盲删；下次读实际事实 |
| 有意图且正式文件匹配 | 核验同步并补记成功，无须为结清旧意图重新下载 |
| 正式缺失且临时文件匹配 | 继续无覆盖发布和保存提交 |
| 正式与临时文件均明确缺失 | 清除已核对意图，回到 `pending` 后重新获取 |
| 正式路径为异内容、目录或符号链接 | 保留现场、意图及 `finalizing`，报告冲突 |
| 正式缺失且临时文件不符 | 保留现场和 `finalizing`，不发布 |
| 保存事务失回执 | 下次若仍有意图则核验补记，若已 `saved` 不重复建版本 |
| 保存成功但临时名未清理 | 保存事实有效，只清理可证明归属的临时名 |

访问/权限错误不等于文件缺失。正式文件核验通过时，临时异常不推翻正式事实，也不授权删除归属不明文件。结清旧意图后仍按本次 `save`/`retry` 规则读当前详情；来源变化再下载，详情失败可使本次 `failed`，已恢复版本保留。

普通失败先关闭请求/句柄再清理本次残片；发布中的文件交恢复流程。仅自动清理本次创建或当前意图明确引用且可证明归属的临时名，不做历史 `.part` 扫描。保存后清理失败须报告而不撤销 `saved`；磁盘、同步、权限等基础资源故障停止当前执行。普通内容冲突可继续其他 Post。

## 模块和资源生命周期

沿用 `src/cli.ts`、`config.ts`、`application.ts` 与 `core/`、`grok/`、`browser/`、`store/`、`files/`。Application 用例接受停止信号和阶段回调，返回业务结果、已知汇总、主错误、持久事实是否记账及附加清理错误。Core 不接触 SQL 客户端、Playwright 对象或原始 JSON。

Run controller 选择并串行安排目标，所有保存入口复用 Post archiver。Grok adapter 解析协议与选择媒体，scheduler 提供共享许可，Browser session 管连接/页面/取消，State store 管事务/锁，Archive files 管写入/核验/无覆盖发布。外部能力不隐藏业务重试或改变 Post 状态。不增加通用 DI、事件总线或多 package。

首次 Ctrl+C 停止新工作，取消可中断请求；已开始文件发布或短事务完成必要一致性收尾再退出。第二次 Ctrl+C 强制 `130`，提示可能遗留 Run、临时文件或自建页；下次按事实恢复。

工厂负责尚未交给 runtime 的部分初始化资源。需要浏览器的批量 Run 按需建立一次 Extension 连接并在各 Post 间复用，每个 Post 的工作页用完即关闭；只读检查与指定 Post 保存各自按命令建立连接。清理可重复，一项失败继续尝试其他独立资源。只关闭程序可证明拥有的页和连接，不关闭用户页或现有 context；连接页通过本次唯一 `clientName` 标记、官方 Extension ID 和唯一匹配确认归属后关闭，归属不明则保留并报告。先停止工作、收尾事实，再关闭工作页与本次连接页并断开连接，最后释放锁和 DB。主业务错误保留，清理错误附加。

浏览器页关闭、连接断开、DB 关闭分别固定等待最多 5 秒；超时报告后继续独立清理并退出，此期限不截断一致性步骤，也不证明底层操作已经停止。Run 摘要写入后的关闭错误仅由命令报告，不重新连接追写。

- **Observable public interface:** CLI 输入、文本、退出码和受控子进程，结合隔离 DB、临时目录与最终持久事实。
- **可观察：** 参数/配置及分阶段启动失败、资源按需获取、真实进程中断、跨进程争锁/丢锁、Ctrl+C、清理错误及结果；浏览器能力使用 mock/fake。
- **不可观察：** 已登录 Chrome/Grok 的现场连接、真实响应、浏览器网络取消或真实页面清理。
- **Prior art:** 暂无正式 CLI 测试。

不模拟整棵 Playwright 对象树，不增加测试专用业务 API。可在已批准观察范围内增补 fixture 和代表性场景；改变接口、改测内部实现或削弱观察能力须重新确认。每张实施票按共享测试契约选择 TDD 或 direct verification，写明行为、预期 red（适用时）和具体 just 验证。

### 自动化验收矩阵

| 范围 | 代表性观察 |
| --- | --- |
| 命令与结果 | 单页不续页、检查不展开详情、指定 Post 共用路径、非 saved 固定重试集合、普通失败继续、停止保留未处理计数、空集合成功 |
| 只读与重复保存 | inspect/status/verify 不写工作，status 仅 DB，verify 不修复，saved 再 save 保留旧版本 |
| 身份与版本 | 错误身份/未知结构、辅助媒体排除、高清优先且失败不降级、来源不变复用、变化后同/不同摘要 |
| 调度与传输处理 | 共享串行间隔、首请求直发、chunk 不取许可、API/媒体各自有限额度、重读详情不重置传输数、长度/类型/文件头/EOF 核验；仅允许上述 PNG 声明、JPEG 内容的已知错标 |
| 错误与停止 | 普通 403/404 对比 429/登录/challenge、阻挡仅本次、等待/在途取消结果处理、未确认停止不进入下一项 |
| 真实 DB 与进程 | 三类事实一致、schema 首次/重复/不匹配、专用会话、双进程争锁、丢锁停止、未收尾摘要未知、提交失回执 |
| 真实文件与恢复 | 意图前后/link 前后/保存提交前后中断、finalizing 矩阵、同内容复用、冲突不覆盖、损坏/缺失/目录变化、同步或清理失败、恢复后检查当前来源 |
| 生命周期与安全 | Run 创建前后失败、工厂部分初始化清理、两次 Ctrl+C、独立清理继续、关闭期限、退出码和凭据脱敏 |

采用少量代表性场景及必要故障点，不穷举交叉组合。DB 使用隔离 Docker PostgreSQL，文件使用临时目录，进程行为使用真实子进程。浏览器相关自动化仅采用方案 A；不建设真实 Chrome + Extension + 本地受控服务的方案 B，也不将其列为延期必补项。

`just gate-core` 在静态检查上运行无需外部服务的快速核心测试；`just gate-full` 再包含真实 DB、文件与 CLI 边界测试。两者均不需要 Chrome、Extension token 或 Grok 登录态。按改动影响选择测试与必要门禁，具体遵循[测试设计与验收](../agents/testing.md)；本节继续定义一期行为覆盖和现场验收要求。

### 现场验收与交付阻断

| 验证项 | 方法与边界 | 失败后的处理 |
| --- | --- | --- |
| 正式浏览器连接 | 锁定运行环境下连接、请求、断开、重新连接；记录自建页及 connect.html 归属和收尾 | 一期首个连接切片解决；不累积依赖不可用连接的实现 |
| 图片、常见小视频 | 正式应用路径核对所选响应长度、EOF、实写/重读大小与摘要 | 不通过不得宣称对应保存能力完成 |
| 真实取消与清理 | 使用普通图片/小视频，在等待首字节、读取和写入阶段停止；观察请求、句柄、临时文件、自建页及 5 秒取消目标，不要求大视频或性能压力场景 | 正式取消链路不通过阻断一期，mock 通过不替代 |
| 既有高清 | 有样本则核对其自身元数据、响应长度、可访问性和完整传输 | 无样本明确记缺口，不无限期阻断；不得声称真实高清已验收 |
| DB、文件和进程恢复 | 最终候选的真实本地边界自动化和恢复事实 | 未通过不得进入二期删除；不声称断电级恢复已验收 |

真实浏览器网络取消与页面检查由普通媒体现场证据承担，不要求建设方案 B。大视频、慢写和内存上界验收已从范围移除。mock 只证明应用处理模拟结果的行为；旧 demo、前端选择规则与静态检查均不代替本项目正式路径证据。

证据记录环境版本、样本类别、去身份化结果和未覆盖范围，不记录凭据、完整私人响应或真实 token。真实 DELETE 留到二期授权样本。
