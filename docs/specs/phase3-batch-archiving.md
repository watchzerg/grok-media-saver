# 三期：批量归档首版

状态：已确认的三期规格。确认日期：2026-09-29。承接决策地图 `grok-media-saver-ozd` 及四张决策票的最终 Resolution；规格发布不表示产品已实现或验收通过。

## Problem Statement

用户已有指定 Post 的完整归档与显式重试能力，但批量清理 Saved 列表仍需反复手工选择 Post。连续执行时，列表可能滞后、重现已处理项或被失败项占满；单 Post 已移除也可能尚未完成本地结清。若把重复出现当成新工作、把本地结清当作列表推进，或把空页当成全部工作完成，会重复请求、错误重置删除额度，或给出不可靠的完成结论。

用户需要一次启动即可逐轮归档，在停止与故障后保留可恢复事实，并清楚区分本次已处理结果、尚未开始的成员、历史未完成工作及未知范围。

## Solution

新增 `archive saved`，每轮读取当前 Saved 第一页，固定该次合法页面的成员，按顺序调用统一 Post archiver。一个 Run 内每个规范化 Post ID 只安排一次完整处理，内部沿用有限重试。只有本轮新确认移除才允许在可取消的固定 5 秒等待后继续读第一页；非空轮没有这种进展时，以 No Progress 结束。

合法空页与数据库所有 Post 工作均按各自目标完成、正常收尾成功共同构成完成条件。Application 提供去重汇总、轮次、列表观察、结束原因及遗留工作快照；CLI 和 status 如实区分已知结果与持久化未知，并给出 `retry` 或重新运行 `archive saved` 的适用提示。

## User Stories

1. 作为本地归档用户，我希望用 `archive saved` 启动连续归档，以便无需逐条输入 Post ID。
2. 作为本地归档用户，我希望每轮处理一次读取确定的成员，以便远端列表变化不改变正在处理的集合。
3. 作为本地归档用户，我希望每个 Post 仍先可靠保存再精确移除，以便批量运行保留单 Post 的安全保证。
4. 作为本地归档用户，我希望同页重复和大小写等价 ID 只处理一次，以便避免重复操作。
5. 作为本地归档用户，我希望本 Run 已处理项重现时跳过，以便成功或失败都不会重置请求预算。
6. 作为本地归档用户，我希望已经结清的 Post 直接跳过，以便不重复核验或打开已完成工作。
7. 作为本地归档用户，我希望普通单项失败后继续本轮其他成员，以便局部失败不浪费本轮可处理内容。
8. 作为本地归档用户，我希望只有新取得的移除证据推动下一轮，以便旧移除事实和本地修复不会造成空转。
9. 作为本地归档用户，我希望旧未知删除意图本轮核对出已移除也算进展，以便正确恢复中断后的批量处理。
10. 作为本地归档用户，我希望新确认移除与本地归档结清分别展示，以便知道远端已不存在但文件仍需补救的情况。
11. 作为本地归档用户，我希望无进展时明确退出，以便第一页被失败或重现项占满时不会无限循环。
12. 作为本地归档用户，我希望有进展后稍作等待再读页，以便批量请求遵守统一节奏。
13. 作为本地归档用户，我希望等待期间可以立即停止，以便不用等到下一轮才能退出。
14. 作为本地归档用户，我希望停止后不再安排 Post 或读页，以便执行范围服从我的停止请求。
15. 作为本地归档用户，我希望已发 DELETE 按既定规则收尾，以便不把中断或失回执误判为未删除。
16. 作为本地归档用户，我希望认证、限流、丢锁与基础资源故障立即阻止推进，以便已有进展不会掩盖运行异常。
17. 作为本地归档用户，我希望非法页面整体失败，以便坏成员不会被悄悄丢弃或被解释为空列表。
18. 作为本地归档用户，我希望合法空页仍检查历史未完成工作，以便空列表不会掩盖保存或归档遗留。
19. 作为本地归档用户，我希望历史 save 和 archive 遗留分开显示，以便只保存工作不会自动变成删除任务。
20. 作为本地归档用户，我希望正常批量启动直接从当前第一页开始，以便不会先执行所有历史 retry。
21. 作为本地归档用户，我希望本次统计按 Post 去重且分类互斥，以便重现项不会虚增完成数量。
22. 作为本地归档用户，我希望未开始的已发现项单独列出，以便知道哪些内容需要下次重新发现。
23. 作为本地归档用户，我希望轮数、最后一轮是否处理完和空页观察分别表达，以便一轮完成不会被说成全局完成。
24. 作为本地归档用户，我希望未读到的数量保持未知，以便界面不展示没有依据的全局百分比。
25. 作为本地归档用户，我希望数据库提交失回执时保留本次已知结果并标注记账未知，以便不误以为事务已回滚或已完成。
26. 作为本地归档用户，我希望 status 区分历史摘要和当前遗留工作，以便不把旧快照当成现在的数量。
27. 作为本地归档用户，我希望异常退出后未知的历史计数不被补零，以便持久事实不会被推测覆盖。
28. 作为本地归档用户，我希望恢复提示区分已开始工作与未开始成员，以便选择 retry 或重新批量发现。
29. 作为本地归档用户，我希望远端已移除后的恢复只接续绑定文件，以便不盲目重发 DELETE。
30. 作为本地归档用户，我希望清理失败单独报告且不抹去已提交结果，以便同时了解业务事实和退出异常。
31. 作为项目维护者，我希望批量行为及故障恢复可在隔离本地环境自动验收，以便开发和修复不依赖私人账号或中途人工操作。
32. 作为项目维护者，我希望自动化证据与真实 Grok 现场验收明确分开，以便模拟通过不会被当成真实副作用已验证。

## Implementation Decisions

### 入口、职责与适用范围

- `archive saved` 是显式批量归档入口；开始处理的成员以 archive 为目标，沿用二期从 save 提升目标、已结清直接跳过及删除恢复规则。不在此次发现并开始处理范围内的纯 save 工作不升级，不自动先执行历史 retry。
- 每次执行创建新 Run。沿用取得执行器锁、处理遗留 Run、创建本次 Run、按需初始化资源及独立清理的顺序；未取得锁不创建 Run。普通命令核对当前 schema，不自动迁移或清空数据。
- Run controller 承担连续读页、固定轮成员、Run 内去重、等待及结束判定。Application runtime 管理同一 Run、专用 DB 会话锁、浏览器连接、共享 scheduler、每 Post 请求预算、结果与资源生命周期。
- Post archiver 继续统一保存、归档和恢复，向 Application 明确报告本次新确认移除；Grok adapter 继续解析精确协议证据。CLI 解析参数、接入信号、展示结果和映射退出码，不自行推导业务完成条件。
- State store 扩展当前 schema 的 Run 命令约束和必要摘要语义，沿用可空 Run 摘要；不新增逐轮历史表、逐请求历史或持久化页成员。Archive files、Browser session 和 scheduler 沿用既有职责。
- 仅面向当前代码、当前 schema 与新启动工作；不支持历史 schema 或进行中旧流程的迁移。需要初始化当前 schema 不等于允许删除已有用户数据。

### 固定成员、去重与预算

1. 每轮只使用一次成功读取的完整合法第一页，保持成员首次出现顺序。Post UUID 统一大小写后去重；同页重复不是协议失败，非法成员或未知包装则整页失败，不部分采纳。
2. 列表只负责发现 Post，不能代替详情的主体媒体选择、版本确认或删除资格。始终读取当前第一页，不翻页、不追随游标绕过失败项。
3. 一个 Run 内，同 Post 最多安排一次完整处理。跨轮重现只跳过调度，成功项和失败项都不重做；已结清项首次安排时直接跳过，不访问文件或远端。尚未开始的成员不预建 Post 工作。
4. 沿用同一 Run、锁、浏览器连接、scheduler 与按 Post 保留的预算；不因跨轮、重复项或重读详情重置 DELETE、核对或媒体额度。
5. 单 Post 内部沿用二期预算：每 Post 每 Run 最多一次 DELETE；恢复旧意图与本次 DELETE 未知后的核对分阶段限额。保存、媒体与核对的其余条件和次数以一二期为准。
6. 每次读页独立适用现有最多两次尝试：网络错误、超时、408 或 5xx 在前次请求确认结束、执行许可仍有效时允许一次重试。读页总期限与共享许可沿用一期；最终失败结束整个 Run，不作为空页或 No Progress。

### 新确认移除与推进

新确认事实必须来自二期认可的精确 DELETE 或同目标核对，且处理前尚未确认移除。列表缺席不构成证据；既有 `remoteObservation = removed` 可能仅来自旧 DB 事实，不能直接作为本轮进展。

| 场景 | 是否计本轮新确认移除 | 处理 |
| --- | --- | --- |
| 本轮 DELETE 得到认可成功证据 | 是 | 分别报告移除、归档结清与记账确定性 |
| 旧未知意图本轮核对得到认可已移除证据 | 是 | 不要求移除由本程序或本轮造成 |
| 新确认移除后本地冲突或补救失败 | 是 | 保留移除事实与未完成结果；普通单项失败继续本轮 |
| 处理前 DB 已确认移除，仅补齐或核验绑定文件后结清 | 否 | 可计归档完成，不作为列表推进 |
| 已结清重现或本 Run 已安排过的 Post 重现 | 否 | 跳过，不重新完整处理 |
| 新证据后记账失回执、丢锁或其他基础故障 | 保留本次已知观察 | 故障优先结束，不据此声称已记账或允许下一轮 |

新确认事实在取得认可证据时产生，必须能穿过后续本地失败或记账未知返回 Application；它与工作完成、持久记账、清理错误分别表达，不需要另建持久事件日志。

单 Post Application 结果以布尔字段 `newRemovalConfirmed` 表达该事实：仅当本次取得认可的精确 DELETE 或同目标 GET 移除证据、且处理前数据库未确认移除时为 `true`；同目标 GET 包括旧 pending 意图的恢复核对，以及本次 DELETE 结果未知后的核对。字段在收到认可响应时立即置位，后续文件失败、丢锁或提交结果未知不得抹去；`remoteObservation` 继续描述本次观察或既有持久事实，`archiveRecorded` 表达归档记账确定性。既有 removed 的本地核验／补救和已结清跳过均为 `false`。批量 Run 可据新字段累计推进事实，不从观察文本或消息推导。

### 结束与故障优先规则

| 场景 | 结果与后续 |
| --- | --- |
| 合法非空轮处理完且有新确认移除，无停止、阻挡或基础故障 | 等待后重新读取当前第一页 |
| 合法非空轮处理完但没有新确认移除，含全部失败、已结清或 Run 内重现 | 未完成，以 No Progress 结束；不追加探测页或轮间等待 |
| 合法空页，所有 DB Post 工作按各自目标完成 | 仅在正常收尾成功后报告完成 |
| 合法空页，仍有 save 或 archive 未完成 | 未完成，分列遗留，不自动升级或 retry |
| 空页后 DB 核对失败 | 故障／无法确认完成，不把未知当零 |
| 读页有限尝试后失败，或页面结构不合法 | 结束，保留读页失败观察，不假装空页 |
| 普通单 Post 失败 | 保留未完成，继续本轮其余成员 |
| 用户停止，包括最后一项收尾、轮间或许可等待 | 不安排下一 Post 或下一次读页，按既定规则收尾 |
| 429、明确登录失效或 challenge | 全局阻挡，不自动等待恢复，不追加核对 GET |
| 浏览器断连、基础 DB／磁盘故障、请求停止无法确认或单项清理故障 | 结束 Run，不自动重连继续，独立资源继续清理 |
| 丢锁或无法确认锁有效 | 不再请求、不再修改 Post 工作事实，不重新取锁接续 |
| 删除相关 DB 提交失回执 | 立即停止，不追写或推断回滚；下次按实际持久事实恢复 |

停止、阻挡和基础故障优先于进展、No Progress 或空页完成判断。首次停止后，已发 DELETE 仅在原 30 秒总期限内收集当前响应；锁和 DB 仍有效时记录认可结果的必要一致性事实，不启动补救下载或新 GET。第二次停止沿用强制退出。断连但锁及 DB 有效时可记录必要中断事实；丢锁后仅报告已知观察。

沿用资源所有权和独立清理期限：不关闭用户页；各项清理失败继续其他独立清理，已提交业务事实不被抹去。Run 摘要提交后的资源关闭错误单独报告，不重新连接追写。

### 固定轮间等待

有进展的非空轮在全部成员处理及逐项收尾结束后，固定等待 5 秒，不新增调优配置。选择依据是现行 scheduler 默认请求间隔 5～8 秒，以其下限作为最小固定轮间停顿；这不是远端列表传播期限或避免限流的保证。

等待使用可取消计时与 AbortSignal；停止时清除 timer/listener，无需等满 5 秒。等待不调用 `requestStarted`、不重抽间隔、不清空预算。结束后再次检查停止、阻挡和锁，下一列表请求仍经过原 scheduler，只等待从上次请求发起以来尚未满足的间隔，不额外叠加完整随机间隔。空页、无进展及异常结束均不安排轮间等待。

### 本次去重摘要

本次已发现是所有成功读取的完整合法页面成员的并集，按规范化 Post ID 去重；非法页不部分采纳。每个已发现 Post 只归入以下一类：

| 类别 | 含义 |
| --- | --- |
| 归档完成 | 本次处理已确认并持久结清，包含恢复后结清 |
| 已结清跳过 | 本 Run 首次安排时已经结清，直接跳过 |
| 未确认完成 | 已开始但失败、停止、阻挡或记账未知，无法确认完成 |
| 未处理 | 已读到但尚未开始处理，不预建 Post 工作 |

四类之和必须等于本次已发现数。共享摘要的 `saved/archived/skipped/unconfirmed/unprocessed` 语义保留；`archive saved` 的 `saved` 为零，不把保存子步骤计为 save 目标完成，CLI 可省略该零项。

同页重复与跨轮重现不增加已发现数，不改变既有结果：此前归档成功仍计归档完成，此前失败仍计未确认完成，不能把重现统一改成已结清跳过。已读到但未开始的项目即使存在历史状态，也不得提前推定本次结果。

本次新确认移除按 Post 去重另列，可与四类结果重叠。新证据后本地未结清或记账失回执，可以同时计新确认移除与未确认完成，明确前者不保证 DB 已记账。已持久结清后清理失败仍计归档完成，清理错误另报。不展示 Saved 全局百分比；尚未读到的内容数量未知，首次读页失败时成功发现零项不等于远端列表为空。

### 轮次、列表观察与结束原因

- 只有成功读取的非空第一页进入处理轮次；开始处理该页即计一轮，包含中途停止和全部重现项的轮次。最后一轮是否处理完单独表达。
- 合法空页不计处理轮，单独作为空页观察；第一页直接为空是零轮。失败读页和请求内部重试不增加轮数。
- Application 分别表达已进入轮数、最后一轮是否处理完、最后一次读页的合法非空／合法空／失败／尚未读取观察。没有处理轮时，最后一轮完成情况不适用，不能伪装成已处理一轮。
- 结束原因区分满足完成条件、空页但有遗留、No Progress、读页失败、用户停止、全局阻挡及基础资源故障；摘要记账确定性和附加清理错误另列。
- 字段名和最小类型扩展沿用现有命名，由实现确定；上述语义和不变量必须有结构化表达，不能仅由 CLI 从消息文本推导。

### 持久摘要、遗留快照与 status

内存累计本次已知统计，在允许安全收尾时随现有 Run 摘要写入必要批量汇总和当时的遗留工作快照。`summaryRecorded` 沿用 `true/false/null`，分别表示确定记录、未记录、提交结果未知。摘要提交失回执立即结束，不重连追写、不假定回滚；终端可继续展示本次已知统计并注明持久化未知。

结束时允许安全查询 DB 的情况下，统一取得全部未完成工作，按 save 和 archive 分列：save 尚未安全保存，archive 尚未归档结清。此数量包含本次与历史遗留，可能与本次未确认完成重叠，不能相加。普通读页失败而 DB 仍可安全读取时也可展示快照，不追加远端请求。

读取失败或无法安全读取时遗留数量为未知；不把初始化空集合或缺失值解释为零，不为补摘要越过丢锁或 DB 提交不确定边界。只有合法空页、全部 DB 工作均完成且正常收尾成功才报告完成；空页但任一目标有遗留为未完成，空页核对失败为故障。

status 只读 DB，展示最近 Run 的持久历史摘要与本次查询的当前未完成工作。若展示历史遗留快照，必须注明为该 Run 收尾时的快照。异常退出或未取得摘要时，不能确认的历史计数、轮数显示未知，不补零、不从当前 Post 状态倒推。status 不检查文件或远端，不修复，不由未结束 Run 推断进程存活。

资源关闭错误可能晚于摘要提交；历史持久成功事实与当前命令因清理失败非零退出分别表达，不抹去已经记录的结果。

### 退出码与恢复提示

沿用现有退出码：`0` 为满足批量完成条件且正常收尾；`1` 为未完成、No Progress、阻挡、故障、记账未知或清理失败；`2` 为参数／配置错误；`130` 为用户停止，仍保留必要事实及清理错误。status 成功读取并展示历史失败仍返回 `0`。

| 情况 | 提示 |
| --- | --- |
| 已开始但未完成 | 查看 status、处理原因后 retry，保持原目标 |
| 已发现但尚未开始 | 再运行 archive saved 重新发现；未预建工作，不保证进入 retry |
| No Progress | 第一页未能推进；失败工作可 retry，已结清重现项不会由 retry 清除；不自动翻页或循环 |
| 空页但有遗留 | 分列 save/archive 遗留并提示 retry，不称全局完成 |
| 删除意图待核对 | archive post 或 retry 先核对同一远端目标 |
| 已移除但未结清 | 接续绑定版本的本地核验或补救，不盲目重发 DELETE |
| 摘要提交失回执 | 保留本次已知结果并标记持久摘要未知，后续 status 读取实际 DB |

例如，本次发现 12 项，可表达为归档完成 8、已结清跳过 1、未确认完成 1、未处理 2；新确认移除可为 9，数据库遗留可另为 save 2、archive 1。后两项统计不是互斥分类的追加项。若第 3 轮中途停止，报告已进入 3 轮、最后一轮未处理完、退出 130。若处理完 3 轮后读到空页但 save 遗留 2 项，报告未完成并退出 1。

### 有状态浏览器 fake 与真实本地边界

- fake 作用于项目浏览器能力接口，分别维护模拟远端存在状态和列表可见状态。DELETE 可改变精确目标状态后丢失回执，列表仍可滞后或重现；同目标核对读取对应远端事实，列表缺席不能代替移除证据。
- fixture 可安排多轮页面、非法响应、认证、限流及必要延迟；记录精确目标和必要时序，以判断追加请求、预算重置或重连。日志不得包含真实凭据或私人响应。
- 跨进程恢复保留同一份模拟远端事实，不能重启 fake 后恢复成删除前状态。采用最小测试 fixture，不扩展产品持久化或建设通用模拟服务。
- DB 提交失回执必须区分真实已提交与未提交：已提交分支实际写入 DB 后丢弃回执，未提交分支使用真实拒绝／回滚；不能只用 fake store 证明提交窗口。
- 文件缺失、冲突、核验、发布使用真实临时文件；进程中断、互斥、丢锁和信号使用真实子进程或 DB 连接故障。测试自行准备并清理隔离资源。

### 人工现场验收边界

浏览器 fake 只证明应用处理模拟远端行为，不能证明真实 Grok 副作用、浏览器网络取消或真实页面清理。正式现场验收由用户在实现交付后独立执行，不作为开发完成条件或遗留阻塞票。实现交付报告必须写明实际覆盖、最终候选与门禁证据，以及“正式现场验收未执行，由用户后续人工操作”。

交付时根据实际 CLI 提供简短人工清单：确认同一 Grok 账号、当前 schema、归档目录及明确授权的操作范围；运行 archive saved 核对轮次、文件与精确移除；观察停止和显式恢复；核对 status、verify 及清理；记录未覆盖媒体形态或具体协议问题。已有账号不切换、删除依据文件不被外部修改的前提继续适用。本规格发布不授权现场 DELETE；发现实际问题后另建具体修复或决策任务。

### 当前实现与决策追溯

当前 Application 提供 `archiveSaved(config, options)`，复用单 Post archiver、同一 Run 的连接／锁／scheduler 与按 Post 请求预算；CLI `archive saved` 已接入该正式用例，按结构化摘要展示结果、结束与恢复提示；status 只读持久历史与当前遗留。`newRemovalConfirmed` 作为唯一推进来源，旧 `remoteObservation` 不充当新进展。当前 schema 的 Run 命令约束包含 `archive-saved`，普通命令与 `db init` 均拒绝不匹配的旧 schema，不自动迁移或清空数据。
