# 二期：单 Post 完整归档

状态：已确认的二期规格。确认日期：2026-09-28。承接 `grok-media-saver-we2` 全部最终 Resolution；产品实现及自动化覆盖以代码和[交付覆盖核对](../research/phase2-acceptance.md)为证据，正式现场验收仍由用户后续人工操作。

本文是二期行为、持久删除事实、恢复和验收的权威正文。Beads 规格入口为 `grok-media-saver-fa3`，引用本文；决策票保留过程与确认记录，不继续作为并行维护的契约正文。产品目标见[产品目标与首版范围](product-goals.md)，模块职责见[架构设计](../../ARCHITECTURE.md)，术语见[领域词汇](../../CONTEXT.md)。

## Problem Statement

用户已经可以保存 Post 主体媒体，但仍需手工移除远端内容。单凭保存成功或 DELETE 调用返回，无法可靠判断是否安全完成归档：文件可能缺失或冲突，请求可能已经执行却丢失回执，数据库也可能提交成功但未返回确认。中断后若直接重发 DELETE，或把旧 `saved` 记录当成删除资格，会产生不必要的远端副作用或错误完成结论。

用户需要明确区分只保存、要求完整归档、移除结果未知、远端已移除但本地尚未结清，以及完整归档；并能在停止、故障或重启后通过同一条处理路径接续。

## Solution

新增 `archive post <Post ID>`，复用一期保存与发布恢复能力：核验当前主体媒体的正式文件，确认保存和精确绑定的删除意图已提交，再移除该 Post。将保存、移除与归档结清分别记账；未知结果先核对同一目标，再按实际持久事实恢复。

保留 `save` 的阶段性只保存含义，统一 `retry` 按每项工作目标接续。`status` 展示已记录事实与恢复提示，`verify` 独立核验确定版本。二期交付可重复调用和跨 Run 恢复的单 Post 归档能力，三期再扩展连续读页调度。

## User Stories

1. 作为本地归档用户，我希望用纯 Post ID 显式启动归档，以便准确指定本次要保存并移除的对象。
2. 作为本地归档用户，我希望安全保存主体媒体后才允许删除，以便避免远端移除后没有完整本地文件。
3. 作为本地归档用户，我希望只保存命令不发起 DELETE，以便继续验证保存能力。
4. 作为本地归档用户，我希望显式归档能将已有 save 目标提升为 archive，以便复用已保存文件并继续完成归档。
5. 作为本地归档用户，我希望后续 save 不降低 archive 目标，以便保护既有归档意图及恢复事实。
6. 作为本地归档用户，我希望 save 拒绝接管未完成的 archive 工作并给出接续入口，以便避免误改删除恢复现场。
7. 作为本地归档用户，我希望单页保存遇到该冲突时报告并继续其他项，以便知道哪些项目未处理。
8. 作为本地归档用户，我希望 retry 自动选择各自目标尚未完成的工作，以便不遗漏已保存但未归档的项目。
9. 作为本地归档用户，我希望 retry 不把纯保存项目升级为归档，以便远端操作始终符合已明确的工作目标。
10. 作为本地归档用户，我希望空 retry 无需浏览器凭据或归档目录，以便仅检查数据库即可确认没有待处理工作。
11. 作为本地归档用户，我希望复用文件时核验当前目录中的大小和 SHA-256，以便旧保存记录不能替代当前安全检查。
12. 作为本地归档用户，我希望文件冲突保留现场且不删除，以便不覆盖已有内容或绕过异常。
13. 作为本地归档用户，我希望只删除绑定的精确 Post，以便关联 Post 和 conversation 不被扩大纳入操作。
14. 作为本地归档用户，我希望删除意图保留所依据的确定媒体版本，以便恢复时不会改用另一个版本。
15. 作为本地归档用户，我希望意图提交未确认时不发 DELETE，以便未知数据库状态不会继续触发副作用。
16. 作为本地归档用户，我希望错误响应和超时不会被解释为远端仍存在，以便不因失回执盲目重发。
17. 作为本地归档用户，我希望未知删除结果先查询同一精确目标，以便依据认可证据判断下一步。
18. 作为本地归档用户，我希望不认可的 200、404、重定向或响应结构保留未知，以便不把弱证据当归档成功。
19. 作为本地归档用户，我希望确认仍存在后重新核验保存和删除资格，以便重试不绕过安全条件。
20. 作为本地归档用户，我希望每 Post 每 Run 的 DELETE 和核对请求有固定预算，以便失败时不会持续请求或重复删除。
21. 作为本地归档用户，我希望删除与核对也遵守共享请求节奏，以便所有业务请求遵守同一调度规则。
22. 作为本地归档用户，我希望首次停止立即禁止新请求，并有界收集已发 DELETE 的响应，以便尽可能保留事实后退出。
23. 作为本地归档用户，我希望第二次停止可以强制退出，以便无需等待故障收尾。
24. 作为本地归档用户，我希望认证失效或限流时停止本 Run，以便人工处理后再显式启动。
25. 作为本地归档用户，我希望断连、丢锁或请求停止不确定时停止推进，以便故障不会扩大到后续 Post。
26. 作为本地归档用户，我希望删除相关提交失回执后结束当前执行，以便下次依实际 DB 恢复。
27. 作为本地归档用户，我希望远端已移除但本地异常时保留移除事实，以便明确剩余工作是本地核验或补救。
28. 作为本地归档用户，我希望缺失文件仅能恢复为删除依据绑定的原版本，以便新内容不会被误当成原归档成功。
29. 作为本地归档用户，我希望原来源不可用时明确报告未结清，以便自行恢复正确文件后再次核验。
30. 作为本地归档用户，我希望已结清 Post 再次处理直接跳过，以便不重新打开工作或触发远端操作。
31. 作为本地归档用户，我希望结果分别说明工作完成、远端观察、持久记账及清理错误，以便理解实际已发生的事情。
32. 作为本地归档用户，我希望退出码能区分成功、未完成、参数错误和停止，以便在终端或脚本中判断结果。
33. 作为本地归档用户，我希望 Run 摘要区分保存完成、归档完成、已结清跳过、未确认完成和未处理，以便准确理解本次处理范围。
34. 作为本地归档用户，我希望无法确认的历史计数保持未知，以便摘要不制造进度事实。
35. 作为本地归档用户，我希望 status 仅查询 DB 并给出恢复提示，以便不触发远端操作或文件修复。
36. 作为本地归档用户，我希望 verify 优先检查删除依据绑定版本且不改写终态，以便独立了解当前文件是否符合记录。
37. 作为本地归档用户，我希望资源关闭失败不抹去已提交归档事实，以便完成结果和清理问题分别可见。
38. 作为维护者，我希望通过隔离 DB、文件、真实子进程与浏览器能力 fake 自动验收，以便实现交付不依赖私人环境或现场样本。
39. 作为维护者，我希望人工现场验收明确留给实现交付后操作，以便不把协议实验或自动化通过误作正式现场验收。
40. 作为后续批量归档的开发者，我希望复用同一 Post archiver 与恢复路径，以便三期只扩展调度及汇总。

## Implementation Decisions

### 适用范围与模块职责

仅针对当前代码、当前 schema 和新启动工作。二期明确扩展或替代一期的命令、retry 集合、持久事实、停止、输出及完成判断；未变更的 Post ID 规范化、主体选择、版本复用、完整性核验、无覆盖发布、共享节奏和资源所有权规则继续沿用一期。二期新增行为不能被一期不含 DELETE 的范围限制阻断；本期自动化交付与人工验收边界以本文为准。

- CLI 增加归档参数、中文结果及既有退出码映射，不创建 DB/浏览器或自行判断删除资格。
- Application runtime 组装用例与资源，管理新 Run、全局执行器锁、停止和独立清理；Run controller 选择固定集合并串行处理。
- Post archiver 统一处理保存、归档和恢复，判断资格、工作完成及错误后的下一步。
- Grok adapter 构造精确请求并解析认可证据；Browser session 执行请求及响应收集，区分可中断请求和已发 DELETE 的收尾。
- API request scheduler 为业务 API、完整媒体、DELETE 和核对提供同一串行许可；业务重试由上层决定。
- State store 扩展工作事实、短事务和目标约束；Archive files 复用核验、发布及恢复能力。
- 保留普通 TypeScript 能力接口，不新增通用 DI、事件总线、独立删除任务系统或另一条下载/恢复路径。

### 资源与初始化

`archive post` 按写入型用例使用 DB、当前归档目录与按需浏览器能力。保存、归档和 retry 共用同一覆盖 Run 的专用会话执行器锁，不因归档目录不同而允许并行。参数和必要配置先校验；普通命令只核对当前 schema，`db init` 显式初始化，结构不匹配报错，不自动迁移或清空数据。

启动及部分初始化清理沿用一期：取得锁后处理遗留 Run，再创建本次 Run；未取得锁不创建 Run。浏览器按用例需要建立连接，含多个 Post 的 Run 复用一次连接，各 Post 工作页逐项关闭。已结清跳过不访问文件或远端；空 retry 的特殊资源契约见下文。

### 入口与工作目标

- 二期新增 `archive post <Post ID>`：安全保存该 Post 主体媒体后移除精确远端 Post。`save post`、`save first-page` 保留阶段性验证用途，调用本身不发起 DELETE；二期不增加 `archive first-page`，连续批量归档由三期负责。
- 在现有 Post 工作上增加最小工作目标 `save` / `archive`，跨 Run 保留，不另建删除任务系统。`save` 以安全保存为完成；`archive` 以安全保存且确认远端移除为完成。`saved` 只表示保存事实，不表示删除授权或完整归档。
- 显式归档同一 Post 可把目标从 `save` 提升为 `archive`；后续只保存操作不自动撤销 `archive`。已有文件仍须按既定规则核验，不能凭旧 `saved` 记录直接 DELETE。
- 工作目标表示用户要求达到的结果，与 DELETE 已经或可能已经发出的持久删除意图区分。删除事实、事务和恢复协议见下文。

### retry 与再次保存

- 保留单一 `retry`。启动时固定跨 Run 未完成集合，每项一轮：`save` 目标选择尚未安全保存者；`archive` 目标选择尚未完整归档者。不把纯保存工作升级为归档；归档目标下的 `saved` 仍可能待处理。
- `retry` 可以延续既有显式归档目标执行 DELETE；未知结果仍先核对，不能盲目重发。普通单项失败继续，停止、全局阻挡或基础资源故障结束执行。
- `save post` 遇到尚未完成的 `archive` 工作时拒绝只保存处理，提示使用 `archive post` 或 `retry` 接续；不改写其归档恢复现场或降低目标。
- `save first-page` 遇到上述工作时报告该项未处理，继续其他项，整次结果非零。完整归档终态遵循架构直接跳过，不核验文件或重新打开工作。

### 查询与资源

- `status` 仍只查询 DB，展示最近 Run 与按各自目标判断的未完成 Post；区分工作目标、保存状态和移除状态，不把已保存表达成已归档。
- `verify` 只读 DB 与当前归档目录，报告核验结果，不改写工作目标或状态，不触发远端操作。
- 空 `retry` 只需 DB：核对 schema、取得执行器锁、按现行规则处理遗留 Run、创建并正常结束零目标 Run，成功退出；不要求浏览器凭据或归档目录。
- 非空执行沿用单执行器、按需资源与新 Run 的生命周期；每次保存、归档或重试均创建新 Run。

### 详情快照与文件核验

- 删除资格沿用本次成功保存所依据的详情快照；详情必须匹配精确 Post ID，并按既定规则选择最高已存在画质。下载成功后不追加详情查询追逐更新，不保证包含快照后出现的高清或同 ID 内容变化。
- 来源变化、失败重试及跨 Run 接续遵循既定详情读取与媒体选择规则；已有删除结果未知时，仍优先核对远端结果。
- fresh save 使用本次发布流程对正式文件完成的大小与 SHA-256 核验；复用使用本次对当前目录文件完成的同等核验。同一次连续处理不再重复完整哈希，跨 Run 接续不能凭旧 saved 记录取得删除资格。
- 运行前提：从文件核验至 DELETE 发出期间，用户及其他程序不移动、修改或删除相关归档文件。已发现的缺失、冲突或文件系统故障阻止删除；缺失或来源变化可以按既定保存路径重新取得文件并重新满足条件，冲突不得覆盖绕过。
- 不声称数据库锁保护外部文件操作；再次核验也不能消除核验结束后的时间窗。沿用当前 DB 与归档目录独立配置，不绑定根目录或搜索旧目录。

### 精确目标与持久删除意图

- 删除意图固定绑定精确 Post ID 和本次已核验、已确认提交的媒体版本引用；版本必须属于同一 Post，可追溯 SHA-256、大小、类型与相对路径。
- 意图未结清时不得改绑另一版本，不能仅从以后可能变化的当前版本引用推断当初依据。沿用既有来源信息，不复制完整详情响应、不保存凭据、不绑定归档根目录。
- DELETE 目标只从绑定的 Post ID 得到，不从媒体 URL、关联 Post 或 conversation 推导。
- 工作目标、保存事实、删除资格、删除意图及移除结果分别表达。删除意图不证明请求已经发出，更不证明已移除；不新增持久的删除资格令牌或独立删除任务系统。

### 请求发出前的顺序与阻断条件

1. 工作目标为 archive；本次详情身份与主体选择正确，正式文件核验通过，保存事务已确认提交，没有未结清的 finalizing。保存函数返回成功本身不足以取得资格。
2. 没有待核对的旧删除意图或未知结果；已有未知结果先走恢复核对，不能直接发起新 DELETE。
3. 确认没有停止、全局阻挡或基础资源故障，提交绑定上述 Post 与版本的删除意图。提交失败或失回执时，本次均不发 DELETE，不推断事务已经回滚。
4. 等待共享请求许可；等待结束、实际发送前，再确认执行器锁有效，没有停止或阻挡，目标与版本绑定仍一致。
5. 任一条件不满足就停止这次删除，保留保存事实；已提交的删除意图交给恢复流程核对，不因调用没有返回成功而擅自清除。

上述边界不承诺本地检查与远端 DELETE 具有原子性，也不消除丢锁检测时间窗。已发请求的停止收尾、响应判据及请求预算按下文执行。

### 正常成功判据

DELETE 绑定已提交删除意图中的精确 Post，禁止重定向，响应目标匹配；完整读取到 HTTP 200、application/json、空 JSON 对象 {}，且无登录或 challenge 异常时，确认移除，不强制追加 GET。单独状态码 200 不足；204、空响应体、非空 JSON 等未认可形状不自动成功。失回执或无法识别的响应进入未知结果核对。

该规则是依据有限正常样本接受的产品判据，不是服务端对所有响应或未来版本的保证。

### 同目标核对与认证前提

- 初次处理及后续跨 Run 恢复必须使用同一 Grok 账号，运行期间不切换账号。这是用户运行前提；程序不验证稳定账号身份，不声称自动发现账号切换，不增加账号健康探测系统。
- 核对只请求删除意图绑定的精确 `https://grok.com/rest/assets/<Post ID>`，禁止重定向、禁用缓存并核对响应目标。列表缺席、页面跳转或媒体地址不可用不替代同目标证据。
- 完整 JSON 响应为 HTTP 404、数字 code: 5、message: "Asset not found"，且无登录或 challenge 异常、无已知不可靠认证上下文时，认可为已确认移除。它表示目标已不存在，不证明一定由本程序删除，也不单独表示完整归档。
- 任意其他 404、HTML、错误目标、异常结构或认证上下文已知不可靠，继续保持未知。当前证据没有证明不同账号永远不会得到同形状 404；接受该判据依赖上述同账号前提。
- 同目标 GET 完整返回 HTTP 200、application/json，根对象 assetId 匹配且 isDeleted 为布尔 false，即可确认仍存在；此时不要求主体媒体已成功解析或下载。isDeleted 为 true、缺失或类型异常等未认可结构继续保持未知，不猜测软删除语义。
- 确认仍存在后重新走现行详情选择、保存或复用核验及删除资格检查，不直接授权再次 DELETE。媒体解析失败不会把已确认存在变成已移除。

### 请求失败与移除结果分别表达

| 情况 | 处理与结果 |
| --- | --- |
| 能确定本次 DELETE 尚未发出，例如发送前停止或资格检查拒绝 | 本次未执行，不由此推翻旧的未知结果，也不擅自清除持久意图 |
| 已发出或可能已发出后超时、断连、响应读不完整、408、5xx 或未知响应 | 移除结果未知，后续先核对同一目标，不套用一期 GET 自动重试 |
| DELETE 返回普通 400、403、404 等错误 | 报告请求失败；没有不产生副作用的协议证据，移除结果仍待核对 |
| 401、明确登录/challenge 或 429 | 全局阻挡，停止新请求，同时保留尚未确定的移除结果 |
| 核对 GET 确认目标仍存在 | 可确定尚未完成移除，后续重发须重新满足资格及下文 DELETE 与同目标 GET 预算 |

核对请求本身的错误不能解释为目标仍存在或已移除；没有认可的结果证据就保留未知。浏览器断连、丢锁等仍遵守基础资源故障停止规则。只有错误响应并不足以证明远端未执行；错误报告、远端结果以及数据库是否已确认记账不得混同。已确认远端事实不因后续本地异常而抹去。

### 单 Post 边界与关联风险

接受两组关联实验的有限证据，继续既定逐 Post 保存后移除。只保存当前 Post 主体媒体并删除当前 Post；实验中的关联保护性保存与完整媒体比较不成为正式归档必经步骤，不扩展关联遍历或成组归档。

按最终验收决策的范围修正，潜在关联风险不预先阻塞自动化交付或三期开发。若后续人工操作发现删除导致其他 Post 主体媒体不可获取的实际证据，再建立具体修复或决策任务并重新讨论范围与架构。现有证据不保证所有关联、未来版本或长期可用性。

### 最小持久事实与完成条件

- 在现有 Post 工作内表达工作目标 save/archive、独立移除状态（尚无待核对意图、意图待核对、已确认移除）、删除依据媒体版本及归档结清标记；保留现有保存状态和媒体版本表。这里确定语义，具体字段名在实现中沿用项目命名，本规格固定其语义与一致性约束。
- 删除意图绑定工作自身的精确 Post 和属于该 Post 的确定媒体版本，可追溯大小、类型、SHA-256 与相对路径。意图待核对和已确认移除时保留版本绑定；结清前保留恢复所需来源信息，普通保存路径不得改写这些恢复事实。
- 意图待核对涵盖提交后未发送、可能发送、请求失败和失回执。不增加声称可靠证明已发送/未发送的持久标记；请求错误单独报告，不设可绕过核对的删除失败状态。
- 历史 saved 加上新确认的移除事实不能自动构成完整归档终态。归档结清才表示保存与移除共同完成；未核验或补救完成时维持未结清，即使历史保存状态仍为 saved。
- retry 启动时固定集合：save 目标选择未保存完成者；archive 目标选择未结清者。归档结清后直接跳过，不因再次出现或再次调用而检查文件或重新打开工作；verify 仍只报告，不改写终态。
- 每 Post 使用当前恢复事实，不建立逐次 DELETE 历史、独立删除任务表、持久自动重试额度或旧数据迁移。

### 意图结清与跨 Run 顺序

1. 已归档结清：直接跳过。
2. 已确认移除但未结清：接续绑定版本在当前目录的保存核验与必要补救，不再发 DELETE 或重新选择主体媒体。
3. 存在未结清删除意图：跨 Run 统一先核对绑定的精确 Post，即使前次可能停在发送前；遵守上文同目标核对判据与同账号前提。
4. 核对确认仍存在：短事务结清旧意图、清除旧删除绑定，保留成功保存版本；事务确认提交后重新按现行详情、文件发布恢复、保存或复用核验规则取得删除资格，不能直接重发。
5. 核对确认已移除：先持久记录移除事实及未结清状态，随后核验绑定版本；核验通过才结清归档。未知则保留原意图和绑定，不重发。
6. 无待核对意图、无移除事实：按现行发布恢复及详情选择、保存、核验路径取得删除资格，确认保存提交且无未结清 finalizing 后提交新删除意图。

恢复时先持久确认移除再做本地核验，避免核验失败抹去远端事实；移除确认后保留未结清标记，避免旧 saved 造成错误终态。正常连续处理已有本次有效文件核验时，允许在同一短事务记录移除成功并结清归档，无须重复完整哈希。

### 短事务与提交失回执

- 浏览器请求、媒体传输、文件核验及发布在事务外；意图提交、旧意图结清、移除确认和归档结清采用短事务，并检查预期状态和精确版本绑定。
- 意图提交未确认成功，本次不得 DELETE；已确认提交后仍遵守共享许可及发送前锁、停止、阻挡、绑定检查。
- 任何删除相关持久写入结果不确定，立即结束当前 Run 的执行，不推断回滚，不在当前进程重连后继续，不声称已记账；保留必要现场。已收到的远端结果与数据库提交是否确定分别报告。
- 下次以实际 DB 为准：无意图且无移除事实则重新取得资格；仍有意图则先核对远端；已移除未结清则接续本地保存；已结清则跳过。结果提交失回执不构成再次 DELETE 的依据。
- 发布恢复沿用一期短事务、版本复用及无覆盖发布规则；普通保存错误不得清除未结清删除事实，普通错误收尾不得覆盖未知提交现场。

### 已移除后的文件补救

- 当前目录的绑定版本正式文件核验通过则结清；不搜索旧归档目录。
- 正式文件明确缺失时，先核对、恢复已有且归属明确的发布意图；没有可恢复文件时，允许用持久保留的原媒体来源尝试下载。
- 补救下载必须符合绑定版本的大小、类型和 SHA-256，按既有无覆盖发布流程恢复。不能改绑新内容、覆盖冲突或把其他版本当成功；沿用媒体共享许可、有限重试、停止及全局阻挡规则。
- 文件冲突、权限错误和核验不符不等于缺失，保留现场并报告；基础资源故障沿用停止规则。
- 原媒体来源不可用时，保留已确认移除与未结清事实，报告无法恢复。用户恢复正确文件后可经 archive post 或 retry 重新核验结清。
- 已确认移除后不请求 Post 详情选择新媒体，也不再 DELETE；必要的远端请求仅用于获取已绑定媒体。这里的本地保存接续包括核验及必要下载补救。媒体传输前可在本地创建并填充自建 Grok origin 工作页，不加载产品页或详情；准备前后检查停止与执行器锁，工作页沿用既有归属及清理规则。

### DELETE 额度与本 Run 核对

- 每 Post 每 Run 最多发起一次 DELETE，不套用一期 GET 自动重试。已发出或可能已发出均不得以调用失败为由归还额度。
- 没有停止、全局阻挡或基础资源故障时，未知结果允许在本 Run 有限核对同一目标；判据遵守上文正常成功与同目标核对规则。正常认可成功不强制追加 GET。
- 核对确认已移除，按既定持久规则记录并结清；核对本次 DELETE 后确认仍存在，短事务结清旧意图并保留未完成归档目标，本 Run 不再 DELETE。
- 新 Run 先核对遗留事实、重新取得删除资格，获得一次新的 DELETE 额度。启动时恢复旧意图的 GET 不消耗 DELETE 额度；确认仍存在并结清旧意图后，可以按既定详情、保存、文件核验及意图提交路径取得本 Run 的删除资格。
- 额度仅在本 Run 内存中计算，不持久化累计次数，不因同 Run 内再次遇到同一 Post 而重置。

### 同目标 GET 预算与共享许可

- 每个核对阶段最多两次 GET：首次加一次条件重试。只有网络错误、超时、HTTP 408 或 5xx 允许重试，而且必须先确认前次浏览器请求已经结束。
- 未认可结构、普通 403、不符合认可判据的 404 等不自动重试；停止、全局阻挡和基础资源故障禁止重试。核对失败不证明目标仍存在或已移除，保留意图及版本绑定。
- 每 Post 每 Run 最多两个核对阶段：启动时恢复旧意图，以及本次 DELETE 未知后的核对。因此最多四次核对 GET、一次 DELETE；认可结果出现即结束该阶段，不轮询等待远端变化。
- 详情与媒体沿用各自既有有限额度，不与核对额度混用；已移除后补救只获取绑定媒体，不重新读取详情选择新版本。
- DELETE、核对 GET 及其重试均经过现有共享串行许可，沿用默认 5～8 秒间隔及现行配置。不增加删除专属退避、轮询节奏或新配置。

### 请求期限与用户停止

- DELETE 和核对 GET 固定总超时 30 秒，从实际发起至响应体读完；共享许可等待不计入。
- 首次 Ctrl+C 停止所有新请求，取消许可等待和可中断请求。DELETE 尚未发出时不发送，已提交意图保留给恢复，不擅自清除。
- DELETE 已发出或可能已发出时，只在原请求截止时间内收集当前响应，不重新计时、不延长、不追加核对 GET、不重发。请求已进行 20 秒时最多再收集 10 秒；该期限不是整个进程退出期限，之后仍有必要记账和资源清理。
- 收到认可成功证据且仍持锁、DB 可用时，完成必要事实写入；否则保留待核对，不声称已持久确认。停止不启动缺失文件补救或其他新远端请求。
- 到期仍无认可结果，保留待核对意图，停止浏览器请求并清理。关闭浏览器请求不证明服务端 DELETE 已撤销。
- 第二次 Ctrl+C 强制退出 130，不等待事实收尾；下次依据实际持久事实恢复。

### 阻挡、断连、丢锁与清理

- 429、明确认证失效或 challenge：停止本 Run 全部新远端请求，包括核对 GET；保留待核对意图并报告阻挡。新 Run 不继承冷却或预算。
- 浏览器断连：结束本 Run，不自动重连继续。没有完整认可响应则保留未知；锁及 DB 仍有效时可记录必要中断事实，不覆盖已确认的远端事实。
- 检测到丢锁或无法确认锁有效：不再发请求，不继续修改 Post 工作事实；本次不重新取锁接续。已收到远端证据可报告，但不得声称已持久记账。
- 锁有效性沿用明确检查点，包含共享许可等待后的发送前检查及删除结果写入前检查；不新增后台锁监控，不承诺消除检测时间窗或将本地检查与远端副作用原子化。
- 删除相关数据库写入失回执：立即停止，不重连追写，不推断回滚；下次读取实际 DB 恢复。
- 超时或取消后无法确认浏览器请求已停止：作为基础资源故障结束整个 Run，不进入核对或下一 Post，保留未知并报告清理失败。
- 自建页、连接与 DB 等独立清理沿用一期每项最多 5 秒和独立清理继续的规则；只清理归属明确的资源。清理超时不证明底层操作已结束，不抹去业务事实，也不截断必要一致性步骤。

### Application 结果与终端呈现

- Application 结构化结果分别保留工作完成情况、本次远端观察、持久记账是否确定以及附加清理错误。CLI 使用明确中文短句，避免用单一归档失败抹去已知事实；不新增 JSON CLI 协议。
- 保存成功但尚未确认移除：展示已保存、归档未完成，并说明尚未发起、核对仍存在或其他具体原因。已保存表示保存记录；只有本次实际做过文件核验，才声称本次核验通过。
- 无法确定 DELETE 结果：展示移除结果未知、待核对，不声称删除失败且目标仍在。
- 已确认移除但本地核验或补救未完成：展示远端已确认移除、归档未结清及本地问题。
- 已收到认可远端成功，但数据库提交失回执：分别展示本次已确认远端移除、数据库提交结果未知、归档结清未确认；不声称回滚或已持久记账。
- 归档已结清而浏览器等资源关闭失败：保留完整归档已记账的事实，另行报告清理失败。

### 退出码

- 沿用 0 / 1 / 2 / 130，不增加删除专用退出码。
- 0：本次目标完成、已结清目标直接跳过或空 retry，且收尾成功。
- 1：目标未完成、移除未知、记账未知、阻挡、基础资源故障或清理失败。
- 2：参数或配置错误。
- 130：用户停止；即使停止收尾期间已经完成归档，也保留已确认事实并报告清理错误。
- status 成功读取并展示历史失败仍返回 0；verify 本次核验异常返回 1。

### 单 Post 与 retry 的 Run 摘要

每个本次目标只归入以下五类之一，Application 提供结构化汇总供 CLI 使用：

| 类别 | 含义 |
| --- | --- |
| 保存完成 | 本次完成 save 目标，包含核验复用 |
| 归档完成 | 本次确认并持久结清 archive 目标，包含恢复后结清 |
| 已结清跳过 | 启动处理时已经归档结清，直接跳过 |
| 未确认完成 | 已开始处理，但失败、停止、阻挡或记账未知，不能确认目标完成 |
| 未处理 | 本次目标集合中尚未开始处理的项目 |

- 单 Post 使用同一口径，目标数量为一；空 retry 全部为零。统计针对本次目标集合，不代表 Saved 全局进度，也不提前规定三期连续读页的统计。
- 逐 Post 结果另行说明保存、移除和具体错误，汇总数不替代这些事实。归档已确认结清后发生清理失败，不将其改计为未确认完成；命令退出仍按清理错误返回非零。
- 摘要在内存累计，正常收尾时写入 Run。本次已知计数与摘要是否成功写入分别表达；Run 摘要提交结果未知时，不声称摘要已持久记录。
- 异常退出后无法得知的计数显示未知，不补零，不从当前 Post 状态倒推历史 Run；不新增逐请求或逐 Run/Post 历史系统。

### status 与恢复提示

- 保留最近 Run 加当前未完成 Post 的视图。未完成集合按既定工作目标选择：save 未完成保存者，archive 尚未结清者；已结清项目不进入该列表。
- 每项展示 Post ID、工作目标、保存状态、移除状态、是否结清以及已记录的最近错误。
- 从持久状态推导恢复提示：待核对删除意图提示使用 archive post 或 retry 先核对远端；已确认移除但未结清提示接续绑定版本的本地核验或补救；其他未完成工作按 save/archive 目标提示接续入口。
- status 只读取 DB，不声称当前文件正常或远端仍存在，不核验或触发修复。未结束 Run 继续提示可能仍在运行或已中断，不推断进程存活。

### verify 与终态

- 有删除依据版本绑定时核验该绑定版本，否则核验当前保存版本。只检查这一确定版本，不遍历全部历史版本。
- 输出核验版本、当前目录中的文件位置，以及通过、缺失、内容不符或访问失败等结果。无可核验保存版本或绑定记录异常时明确失败，不猜测其他版本。
- 本次通过仅表示本地文件符合记录，不确认远端状态，不自动结清归档，不修改工作目标或持久状态，不触发远端请求或自动修复。
- 已结清但文件异常时，同时展示数据库已记录归档结清与本次文件核验异常，退出 1；不改写终态。archive post 再次遇到已结清 Post 仍直接跳过，不检查文件或重新打开工作。
- 尚未结清的工作即使 verify 通过，仍需通过 archive post 或 retry 完成恢复及结清。

- **可观察：** 参数、启动、退出、信号、真实进程中断、跨进程争锁/丢锁和清理结果；浏览器能力使用 mock/fake。
- **不可观察：** 真实浏览器协议、Chrome/Extension 连接、网络取消或页面清理。
- **Prior art:** [单页保存](../../tests/cli/save-first-page.test.ts)、[retry](../../tests/cli/retry.test.ts)、[指定 Post 保存](../../tests/cli/save-post.test.ts)及现有 CLI/DB/文件/进程测试。既有提交失回执测试先在真实 DB 完成提交再丢弃回执，真实子进程用于信号、争锁和中断；不能只用 fake store 替代这些边界。

浏览器 fake 作用于项目能力接口，不模拟整棵 Playwright 对象树；它只能证明应用对模拟响应的处理，不能证明真实远端副作用。改变观察接口、改测内部实现或削弱观察范围时须重新确认；在上述范围内补充 fixture、代表性分支和测试组织不需重复确认。

### 自动化验收矩阵

采用代表性关键窗口与恢复分支，不穷举交叉组合。

| 范围 | 必须观察的行为 |
| --- | --- |
| 工作目标与删除资格 | save 不触发删除；archive 依次满足当前正式文件核验、保存提交、绑定意图提交；身份错误、文件冲突、未结清 finalizing、提交不确定及发送前停止/阻挡/丢锁阻止 DELETE。缺失经既定路径恢复后须重新满足资格。 |
| 精确目标与响应判据 | 请求只针对绑定 Post；认可成功、确认仍存在、未知分别处理；错误目标、重定向、任意 404、未知结构不能误判移除成功。 |
| 未知恢复与预算 | 遗留意图先核对，未知不盲目重发；每 Post 每 Run 最多一次 DELETE、两个核对阶段且各最多两次 GET；仅既定错误允许条件重试，共享许可与停止规则对所有请求生效。 |
| 真实 DB 与进程恢复 | 删除意图、旧意图结清、移除确认及归档结清覆盖实际已提交但回执丢失和未提交分支；在意图提交后、远端结果返回后及记账前后选择必要真实进程中断点，重启后依据实际事实恢复，不在不确定提交后继续执行。 |
| 已移除后的文件接续 | 保留移除事实；只核验或补救绑定版本；缺失可按规则恢复，冲突不覆盖，错误内容不能改绑成功；不再读详情选择新媒体或 DELETE。 |
| 停止、故障与清理 | 发送前停止、已发 DELETE 后首次停止的原期限响应收集、第二次强制退出、认证/限流阻挡、断连、丢锁、无法确认请求停止；不得越界追加请求或修改工作事实，独立清理继续，清理错误不抹去业务事实。 |
| 结果、查询与终态 | 远端观察、持久记账及清理结果分别表达；退出码、Run 分类及摘要不确定性正确；status 只读 DB，verify 检查确定版本且不修复；已结清 Post 再次处理直接跳过，即使文件后来缺失也不重新打开工作。 |

远端执行后失回执由受控浏览器能力模拟；DB 提交、文件恢复和进程中断使用真实本地边界。fake 不证明真实远端副作用或浏览器行为。具体成功判据、预算和恢复语义以本文 Implementation Decisions 为准。

### 完全自动化的实现完成条件

- 实现票与二期自动化交付不依赖用户 Chrome、Extension、Grok 登录态、私人数据库、真实删除样本、人工操作或现场授权。
- 锁定 Bun、Docker 等属于测试基础设施要求，不承诺在缺少必要运行工具时也能运行。测试自行准备数据、创建隔离 PostgreSQL 和临时目录、注入故障、验证恢复并清理；不以 mock 冒充真实 DB/文件/进程证据。
- 每票通过 just test 运行覆盖改动的最窄有效验证，按项目和执行流程完成静态检查及必要门禁；新增可观察行为采用 TDD，行为不变且既有覆盖充分时采用 direct verification。实现票注明行为、适用的 expected red 和具体 Verification。
- 二期最终干净候选必须通过一次无筛选 just gate-full，并核对矩阵实际覆盖。候选因修复改变后重新运行；不能拼接不同候选的成功片段，失败、收集失败或零匹配不算通过。
- 回归覆盖一期保存/发布恢复、版本与文件冲突、共享调度、单页与 retry、Run 级连接复用、逐项工作页关闭和最终断开，以及清理失败不抹去已提交事实。浏览器回归用能力 fake，不因此追加真实环境前置任务。

### 人工现场验收与三期交接

- 正式现场验收由用户在实现交付后人工操作，不纳入本规格的自动化实现票完成条件，不设为未完成子票或三期开发阻塞项。
- 图片/视频 DELETE、在途停止样本及真实多 Post 保存 Run 均不作为自动化交付前置要求；本规格不授权新的现场 DELETE，不安排新现场实验。
- 实现交付报告须明确“正式现场验收未执行，由用户后续人工操作”，并附简短操作清单。现有真实浏览器缺口仅作人工核对提示，既有前置协议实验不算正式产品验收。
- 自动化门禁和契约覆盖通过后，允许实现票关闭、二期自动化交付完成，并交给三期开发。交接能力是统一 Post archiver 的可重复调用、可跨 Run 恢复的单 Post 归档；三期扩展调度与汇总，不另建保存/删除/恢复路径。
- 必需自动化行为失败须解决，不以潜在现场问题预先阻塞自动化完成。未来人工操作发现协议、停止、清理或关联影响的具体问题，再建立相应修复或决策任务。
- 现有关联证据仍仅覆盖已观察样本。原地图条件性 fog 转为上述重新讨论触发条件，不预建关联遍历或成组归档，不继续保留为未决问题。

### 验证入口与后续人工操作提示

模块覆盖沿 S1/S2 贯穿 CLI、Application runtime、Post archiver、Grok adapter、共享 scheduler、State store、Archive files 与浏览器能力接入。测试使用当前锁定工具链、隔离 Docker PostgreSQL 与临时归档目录；不访问私人 DB 或既有归档资产。

按实际切片选择 `just test core`、`just test tests/cli/<实际测试文件>` 或带 `-t <name>` 的最窄有效 suite。具体实现票必须填写有效路径、预期行为和验收证据，不将此处占位路径作为可执行命令。新增行为按 TDD，已有充分回归的行为不变改动按 direct verification；遵循[测试设计与验收](../agents/testing.md)及其共享规则。

当前 `just gate-core` 包含 Bun 版本检查、TypeScript、核心测试和 Biome CI；`just gate-full` 再运行真实 CLI/DB 边界测试。最终候选需通过无筛选 `just gate-full` 并核对上述矩阵覆盖；仅命令成功不证明未覆盖的行为。收集失败、零匹配或缺失环境不能作为通过证据。

正式现场验收留给实现交付后由用户执行。交付时结合届时实际 CLI 给出简短清单：

1. 使用同一 Grok 账号，准备明确授权的精确 Post 样本、当前 schema 和归档目录；不在执行期间切换账号或修改待删除依据文件。
2. 通过正式 `archive post` 核对主体媒体、保存文件、精确移除与结清输出；样本不足的媒体形态如实记为未验证。
3. 核对 `status`、`verify` 与再次处理已结清 Post 的只读/跳过行为，分别记录远端事实和当前文件结果。
4. 在明确操作范围内观察停止、显式 retry、连接及自建页清理；不为补证据盲目重复 DELETE 或扩大样本。
5. 报告实际覆盖与缺口；发现协议、取消、清理或关联影响问题时另建具体修复或决策任务。

这份清单不是现场执行授权，也不是本轮待完成验收任务。现有连接复用后的完整多 Post 保存 Run、真实断连及连接页关闭失败缺口只作后续人工核对提示，不阻塞二期自动化交付。

## Out of Scope

- 三期连续读页、轮间等待、No Progress、批量归档入口及全局进度设计；本期不增加 `archive first-page`。
- Web UI、多账号、后台服务、云部署、完整 JSON CLI 协议、交互面板或独立的长期只保存产品模式。
- 关联遍历、成组归档、conversation 删除、生成上下文、主动生成或增强媒体；实验中的保护性保存不进入产品必经路径。
- 旧 schema、试运行数据或进行中工作迁移，跨版本兼容、自动清空数据和通用迁移框架。
- 独立删除任务表、逐次 DELETE 历史、逐 Run/Post 历史、持久重试额度、持久删除资格令牌、账号健康探测或后台锁监控。
- 自动重连继续执行、无限轮询、删除专属退避或新配置、跨 Post 去重、sidecar 元数据、搜索旧归档目录。
- 大视频专项支持、慢写和峰值内存验收、字节级续传、下载方案 B、真实 Chrome + Extension + 本地受控服务测试方案 B。
- 本次规格发布不执行产品实现、拆分实施 tickets、应用门禁、现场 DELETE 或正式现场验收。实现阶段须执行上述自动化验收，现场由用户另行操作。

### 一期契约与当前代码

[一期可靠保存规格](phase1-saving.md)继续维护保存、媒体完整性、版本与发布恢复等未变更契约；二期明确改变的部分以本文为准，一期文档不改写成已经实现二期。当前源码包含保存用例、保存工作与媒体版本、真实 DB/文件/CLI 测试及 Run 级浏览器连接复用；已加入工作目标和归档结清标记，保存入口保护未结清归档工作，已结清工作直接跳过；retry 已在启动时固定未完成工作集合，按各项 save/archive 目标复用同一 Post archiver 接续，包含未结清归档工作，纯保存项不升级为归档。已提供正式单 Post 归档正常路径、精确 DELETE 能力、持久删除意图、正常成功的移除确认与归档结清写入。遗留删除意图安全保留并拒绝直接重发；已支持在途首次停止的原期限响应收集、认可成功的必要记账与停止退出，期限取消未确认停止时保守结束工作推进并报告清理故障。已支持遗留意图的首次精确 GET 核对、原始响应判据分类、认可不存在后的独立移除确认，以及绑定文件当前核验通过后的独立结清；移除确认与恢复结清的真实提交失回执/未提交均停止推进。文件缺失或冲突保留已移除与未结清，用户恢复正确文件后再次调用仅做本地核验。首次核对遵守共享许可、发送前检查、30秒总期限及可中断收尾；未知保留原意图，不直接重发。认可仍存在后先以独立短事务结清旧意图和旧绑定，保留保存版本；仅在提交确定后重新读取详情并沿用保存、发布恢复与文件核验路径，符合资格后本 Run 发起一次新 DELETE。旧意图结清实际提交失回执或未提交均立即停止，后续按真实 DB 恢复。现已支持本次 DELETE 未知后的有限核对：认可已移除时沿用本次有效文件核验并独立记账结清，认可仍存在时结清意图并保持未完成，本 Run 不再次 DELETE。恢复与本次未知两阶段各最多两次 GET，仅请求已确认结束的网络错误、超时、408 或 5xx 允许一次条件重试；所有请求沿用共享许可，停止、阻挡或基础故障禁止追加。Run 持有按 Post 的阶段和 DELETE 额度，重复遇到不会重置。已支持已移除后的绑定文件补救：仅检查当前目录，先恢复严格匹配绑定版本的发布意图；必要时从保留来源下载，来源声明类型与实际保存类型分别保留；沿用一期 PNG 声明、JPEG 内容特例，最终大小、实际类型和 SHA-256 必须完全符合绑定版本，沿用无覆盖发布、共享许可及最多两次媒体尝试，不再请求详情或 DELETE。冲突、失败、停止与阻挡保留移除事实和绑定，发布及结清写入未确认时立即停止；正确文件人工放回后可仅核验结清。已提供单 Post、单页保存及 retry 的互斥五类 Run 汇总，Application 分别返回已知计数和摘要记账确定性；摘要写入失败或清理失败保留已知 Post 事实，status 展示持久摘要或未知数量，不倒推历史计数。正式浏览器现场验收未执行，由用户后续人工操作。

一期自动化与现场历史记录见[一期验收记录](../research/phase1-acceptance.md)。旧门禁结果不作为二期候选验证，历史保存 `saved` 不等于完整归档。
