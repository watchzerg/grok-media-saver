# 产品目标与首版范围

状态：已确认的目标基线。确认日期：2026-09-25。

本文是本项目产品目标与首版范围的权威正文，描述预期能力，不表示这些能力已经实现。具体实现规格、执行任务与验收记录以 Beads 为入口并引用本文；模块设计与技术决策在后续架构文档中确定。

## 项目定位

grok-media-saver 是面向个人本地使用的归档工具：利用现有 Chrome 登录态，将 Grok Saved 列表中的 AI 生成图片和常见小视频可靠保存到本地，并在保存成功后移除对应远端 Post。

2026-09-26 范围修订：用户明确视频通常较小，当前不考虑大视频专项支持、慢写压力测试、回压上界或峰值内存验收。这些不是交付阻断项，也不作为延期必补项；不据此新增文件大小阈值或拒绝规则。普通媒体的完整性、超时、停止、资源清理和文件恢复仍按现行规格验收。

核心价值是让用户显式启动一次归档后，工具能够持续推进；遇到中断或失败时，保留足够的信息，让用户知道发生了什么、哪些工作尚未完成，以及如何继续。

唯一需要遍历的列表入口是 `https://grok.com/imagine/saved`，页面支持向下滚动动态加载。此前讨论中的“History / All”是对此入口的不准确称呼，不表示另有列表来源。入口 URL 纳入配置，默认使用上述地址；不扩展任意抓取来源。

## 归档范围与产物

- 以 Saved 列表 中的 Post 为处理单位，每次只保存当前 Post 自身的完整媒体。
- 本地归档产物包括媒体文件，以及识别来源、判断完整性和支持恢复所需的必要信息。
- 不主动扩展到关联 Post、整个 conversation 或全部生成历史，不生成新媒体或提升媒体质量。
- 首版不提供完整生成上下文归档、可浏览图库、标签管理或搜索。

## 核心流程与完成含义

归档按以下方向推进：读取 Saved 列表第一页，逐条安全保存当前 Post 自身的媒体，精确移除对应远端 Post，再读取新的第一页。

单个 Post 完整归档需要同时满足两个结果：

1. 当前 Post 自身的媒体已经完整、安全地保存在本地。
2. 对应远端 Post 已确认移除。

保存与移除分别记录结果。“已保存但未移除”是清楚可见、能够继续处理的未完成状态，不能报告为完整归档成功。

产品以“保存后清理”为主模式。“只保存”可以作为前期验证能力，首版不要求将其作为长期维护的独立产品模式。

## 可靠性原则

- 只有确认本地保存安全，才允许移除远端 Post。
- 中断后能够依据持久事实继续处理，避免依赖用户手工猜测进度。
- 遇到无法判断的状态时，保留未完成结果并说明原因，不推断成功。
- 登录失效或受到限制时，允许停止并等待人工处理。
- 用户能够理解当前状态、停止原因及未完成事项，并能够停止归档和恢复工作。

可靠性优先于速度和无人值守程度。首版不承诺永远无需人工介入，也不以最大下载吞吐量为目标。

## 运行方向

- 首版面向个人本地使用，以 CLI 为入口，由用户显式启动归档。
- 复用现有 Chrome 登录态，通过 Playwright Extension 提供连接路径。具体连接入口保留调整空间，实验中的内部调用方式不构成固定的产品契约。
- 单执行器串行处理归档工作。
- Web UI 根据后续实际需求另行规划。

## 首版范围与完成标准

首版应能够持续处理 Saved 列表 中的 Post，完成安全保存和远端移除；遇到常见失败或进程中断后，能够恢复或明确要求人工处理；结束时能够说明已完成和未完成的结果。

首版包含批量归档，以及使用该能力所需的状态查看、停止、恢复和失败处理入口。单 Post 可靠归档是通向首版的核心能力里程碑，单独完成它不代表批量归档首版已经完成。

首版不包含 Web UI、多账号、云部署、旧项目数据或进行中任务的迁移，以及前述媒体管理功能。按新项目、新数据库和新启动任务设计。
